IEC 62056-21 电表模拟器使用说明

用于排查 MG301 DTU 对接 IEC 62056-21 电表时的“不工作”问题：让 DTU 去读模拟器，看握手卡在哪一步，并直接得到修正建议。程序界面支持 English（默认）、简体中文、Español，菜单「帮助 → 使用方法」（F1）里有三种语言的简版说明。

一、概述

模拟器扮演电表（从站），DTU 扮演主站。DTU 发出的每一条报文都会被逐字节记录和解析；不符合协议时，日志会指出问题并给出正确写法。

核心能力：

  • 跨平台、免装 Python：提供 Windows 安装程序、macOS 磁盘映像（DMG）、Linux 压缩包，双击即可运行。
  • 全模式：支持 IEC 62056-21 的 Mode A、B、C、D、E。
  • 多种连接：串口、TCP 服务端、TCP 客户端、UDP。
  • 过程可视、日志可导出：状态条逐步显示握手过程，日志可导出为 TXT / CSV。
  • 报文诊断：主站报文有问题时，日志指出问题并给出正确报文。
  • 多语言、内置帮助、关于、版本更新检测。
文件用途
电表模拟器.py图形界面主程序
meter_core.py协议引擎和传输层；也可以作为命令行版单独运行，适合无界面的 Linux 机器
app_info.py版本号、开发者信息、更新源（GitHub 仓库）
i18n.py / translations.py多语言切换和英文、西班牙文译文表

.github/workflows/build.yml在 GitHub 上自动测试并打包三个平台的安装包，推送版本标签时自动发布

二、快速开始

1. 安装

系统安装包安装方法
Windows 10/11（64 位）MeterSimulator-版本-windows-setup.exe双击安装，默认装在当前用户目录，不需要管理员权限；完成后在开始菜单打开
macOS（Apple 芯片）MeterSimulator-版本-macos-arm64.dmg打开 DMG，把 MeterSimulator 拖到 Applications 文件夹
macOS（Intel）MeterSimulator-版本-macos-x86_64.dmg同上
Linux（x86_64）MeterSimulator-版本-linux-x86_64.tar.gz解压后运行 MeterSimulator/MeterSimulator
安装包目前没有做代码签名，首次打开时系统会拦截：
  • macOS：提示“无法验证开发者”时，到「系统设置 → 隐私与安全性」点「仍要打开」。
  • Windows：SmartScreen 提示时，点「更多信息 → 仍要运行」。
要彻底消除提示，需要公司的 Apple Developer ID 和 Windows 代码签名证书。

也可以直接用源码运行：

pip install -r requirements.txt
python3 电表模拟器.py        # macOS / Linux
py 电表模拟器.py             # Windows

2. 接线（串口方式）

  • RS-485：USB 转 485 模块的 A 接 DTU 的 A，B 接 B，最好共地。
  • RS-232：TX 接 RX，RX 接 TX，GND 接 GND。
  • macOS 上请选择 /dev/cu.* 开头的端口；Windows 上是 COMx；Linux 上是 /dev/ttyUSB*，当前用户需要在 dialout 组里。

3. 典型 Mode C 设置

项目标准做法若 DTU 使用固定波特率
初始波特率300与 DTU 一致，例如 9600
数据位 / 校验 / 停止位7 / E / 17 / E / 1
波特率字符5（握手后切到 9600）与初始波特率对应，例如 9600 对应 5，此时不切速

设置好后点击「▶ 启动」，再让 DTU 开始抄表即可。

三、功能详解

1. 连接方式

方式说明波特率切换
串口直接连接 DTU 的 485 或 232 口真实切换，发完数据后恢复初始波特率
TCP 服务端模拟器监听端口，等待主站连接不适用，自动跳过
TCP 客户端模拟器主动连接主站，断线后每 3 秒自动重连不适用
UDP应答发给最近一次发来数据的主站；Mode D 主动推送时可指定目标地址不适用

如果主站在网络透传时保留了 7E1 的校验位（字节最高位为 1），请勾选「接收时去掉最高位」。

2. 协议模式

模式流程默认初始波特率 / 波特率字符
A请求 → 标识 → 数据，全程不切速300 / J
B请求 → 标识 → 按字符 A~F 切速 → 数据，没有 ACK300 / E（9600）
C请求 → 标识 → ACK 选项 → 切速 → 数据读取或编程模式300 / 5（9600）
D电表以 2400 bps 主动推送，不响应请求；可手动推送或定时推送2400 / 3
E同 Mode C 握手，标识带 \2；ACK 选 2 后进入 HDLC 模式300 / 5

编程模式（Mode C/E，ACK 中 Y=1）支持：P1/P2 口令；R1~R6 读、W1~W5 写、E1/E2 执行；B0 结束会话；主站发 NAK 时电表重发上一条报文。写入的值会实时更新到数据项表。

3. 电表设置

字段说明
厂商ID3 个字母。第 3 个字母小写表示最短响应时间为 20 ms，大写为 200 ms
波特率字符写在标识报文中，主站据此切速
表地址留空表示接受任意地址。填写后，地址不符的请求不予应答（与真实电表一致）
编程口令P1 明文口令校验。留空表示不校验
响应延时每次应答前的等待时间，标准范围为 20/200 ~ 1500 ms，超出范围时日志会提示
ACK 超时发出标识后等待 ACK 的最长时间
故障注入可选：不回复标识、收到 ACK 后不发数据、数据 BCC 故意出错。用于验证 DTU 的容错能力

关闭程序时会记住当前的连接和电表设置，下次打开自动恢复。

4. 连接过程

界面中部的状态条按当前模式显示每一步，例如 Mode C 为：请求 → 标识 → ACK确认 → 切速 → 数据/编程 → 结束。颜色含义：灰色未开始，黄色进行中，绿色 ✓ 完成，红色 ✗ 失败，浅灰 – 跳过（例如网络连接不需要切速）。出现问题时，状态条下方直接显示问题和建议。

5. 日志与导出

  • 收发报文同时显示可读形式（如 <STX>、<CR><LF>）和 HEX，并带毫秒时间戳。
  • 日志颜色：蓝色为收到的报文，绿色为发出的报文，红色粗体为问题，紫红色为建议，橙色为警告。
  • 勾选「只看问题」后只显示问题、建议、警告、连接和会话分隔。
  • 「导出日志…」可保存为 .txt（可读文本）或 .csv（Excel 可直接打开）。
  • 勾选「自动保存日志」后，日志实时写入日志文件夹，程序意外退出也不会丢失。安装版写入「文稿/MeterSimulator Logs」，源码运行时写入程序目录下的 logs/。菜单「文件 → 打开日志文件夹」可直接打开。
  • 日志使用当前界面语言；把英文日志发给国内同事前，可先切到中文再复现一次。

6. 报文诊断

以下情况会在日志中标为「问题」，并给出建议：

场景日志给出的建议
请求缺少 <CR><LF>给出完整请求和 HEX，并提醒很多真实电表会因此不应答
请求格式错误（缺少 ? 或 !）正确格式 /?地址!<CR><LF>
请求地址与电表地址不一致应填写的地址，或改用广播请求
收到标识后没有发 ACK检查 7E1 和波特率字符；DTU 若按 Mode A/B 工作，可切换模拟器模式验证
没发 ACK 就重发请求说明 DTU 没解析出标识，列出排查顺序
ACK 不完整，或 V/Z/Y 无效给出该电表应收到的完整 ACK 和 HEX
主站要求的波特率高于电表提议Z 只能等于或低于标识中的字符
字节最高位被置位判定为 7E1 与 8 位不匹配，并说明串口和网络两种场景下的改法
乱码判定为波特率不一致或切速时机不对
Mode C 下收到 HDLC 请求建议切换到 Mode E，或改用读数 ACK
编程模式 BCC 错误给出正确的 BCC 值、计算范围和整条报文的正确 HEX
口令错误、未登录就读写、读不存在的地址给出正确口令格式；读地址时列出相近或可用的地址
回显提示 RS-485/光口回环，回显不参与解析

7. 界面语言

菜单「Language / 语言 / Idioma」可在 English、简体中文、Español 之间切换，默认英文，选择会被记住。切换时如果模拟器正在运行，会先询问并停止；已有的日志和设置会保留。界面文字、日志里的问题和建议、导出的 CSV 表头都会跟随语言变化。

8. 使用方法与关于

  • 帮助 → 使用方法（快捷键 F1）：程序内置的说明，内容跟随界面语言。
  • 关于（macOS 在应用菜单，Windows/Linux 在「帮助」菜单）：显示版本号、开发者 InHand Networks、联系邮箱、网站、更新源和运行环境。邮箱和网站可点击打开。

9. 版本更新检测

程序从 GitHub Releases 读取最新版本号，与当前版本比较：

  • 帮助 → 检查更新…：手动检查，总会给出结果（已是最新、发现新版本或失败原因）。
  • 启动时自动检查：默认开启，启动 3 秒后在后台检查，只在有新版本时弹窗；可在「帮助」菜单关闭。
  • 新版本弹窗显示更新内容，提供「下载新版本」（直接下载本平台的安装包）、「稍后提醒」「跳过此版本」。
更新检测需要先在 app_info.py 中把 GITHUB_REPO 设为公开仓库，例如 "inhand/meter-simulator"。目前为空，「检查更新」会提示“未配置更新源”。

10. 发布新版本

  1. 修改 app_info.py 中的 VERSION，例如 1.0.1。
  2. 提交代码并推送标签 v1.0.1。
  3. GitHub Actions 自动运行测试，然后在 Windows、macOS（Apple 芯片 / Intel）、Linux 上分别打包，并创建 Release。已安装的程序即可检测到新版本。

本地只能打包当前系统的安装包：

pip install pyinstaller pyserial pillow certifi
python packaging/build.py     # 输出到 dist/

四、常见问题

DTU 读不到数据，先看哪里？

先勾选「只看问题」，看状态条在哪一步变红：

  • 「请求」没亮：模拟器没收到任何报文，检查接线、端口和波特率。
  • 停在「ACK确认」：最常见的原因是 DTU 没正确解析标识，或者 DTU 实际按 Mode A/B 工作。
  • 「切速」之后出现乱码：DTU 切速的时机或目标波特率不对。

用 pwitab 走真实串口测试时读不到数据

pwitab 发出 ACK 后要等约 0.75 秒才切换波特率。请把模拟器的响应延时设为 1000 ms 左右（标准上限为 1500 ms），否则数据会在它切速之前发出。

「检查更新」失败

  • 提示“未配置更新源”：app_info.py 的 GITHUB_REPO 为空。
  • 提示“还没有发布过版本，或仓库不是公开仓库”：仓库还没有 Release，或仓库是私有的（程序无法匿名读取私有仓库）。
  • 网络错误：检查电脑能否访问 api.github.com。

Mode E 能抄 DLMS 数据吗？

不能。模拟器只实现到进入 HDLC 为止，之后只记录收到的帧，不实现 DLMS/COSEM 应用层。如果需要，可以另行接入 Gurux 等 DLMS 服务端。

已知限制

  • Mode A/B 只支持数据读取，不支持编程模式。
  • 读数不支持分块（EOT）传输；不支持厂商自定义模式（Y=6~9）。
  • 安装包未做代码签名，首次打开会被系统拦截（见“安装”一节）。
  • macOS（Apple 芯片）安装包已在本机构建并验证能启动；Windows、Intel Mac、Linux 安装包由 GitHub Actions 构建，尚未实测。
  • 串口自测用的是虚拟串口，只验证了报文流程；7E1 和切速的实际电气时序，需要用两根 USB 串口线对接确认。
